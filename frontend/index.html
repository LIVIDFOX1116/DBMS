Pipeline

From raw chain data
to a triaged alert

Five stages, each one a real script in this repo — not a diagram of something that doesn't exist yet.

1
Ingest
Etherscan → Postgres

A bounded BFS crawl pulls transactions and token transfers around a seed address into a normalized schema.

2
Snapshot
Graph → Parquet

The subgraph for a block range is exported and versioned, so every analysis run points at a fixed graph.

3
Analyze
PageRank · Louvain · BFS

RAPIDS cuGraph on a GPU laptop, pandas + NetworkX everywhere else — picked automatically at runtime.

4
Detect
Heuristic alerts

Cluster shape and wallet behavior are checked against four pattern heuristics; matches become alerts.

5
Review
Dashboard triage

An analyst works the alert queue, drilling into the wallet, the cluster and the graph behind every flag.

✦ Case Study

The Poly Network
exploit, traced

FrameCheck's default seed is 0xC8a6…8963 — the address behind the August 2021 Poly Network exploit, one of the largest and best-documented DeFi hacks on record. The on-chain trail is public and the funds were ultimately returned, and its fan-out/consolidation structure gives PageRank, Louvain and BFS something real to find. Point the pipeline at a different address by changing CASE_STUDY_ADDRESS in .env — nothing else changes.

FAQ

Questions,
answered

Straight answers, including the limitations — see docs/API_CONTRACT.md for the full list.

What is FrameCheck?
+
A GPU-accelerated Ethereum transaction-graph analyzer and framing audit, built as a DBMS course project. It ingests a bounded on-chain subgraph, runs graph algorithms against it, surfaces the results — wallet risk, clusters, pattern alerts — through this dashboard, and then audits every flag it raises for whether an outsider could have produced it just by sending the wallet unsolicited funds.
Where does the data come from?
+
A BFS crawl over the Etherscan API, seeded from one address and bounded by hop count and block range. Everything lands in PostgreSQL under a documented schema before any analysis runs.
Do I need a GPU to run it?
+
No. The graph backend falls back to pandas + NetworkX automatically whenever RAPIDS isn't installed — that's how this whole pipeline was built and unit-tested without touching a GPU. RAPIDS cuGraph only kicks in on a machine where it's actually available.
What patterns does it detect?
+
Cluster and wallet heuristics for four pattern types — Sybil fan-out, wash trading, mixer behavior, and peel chains. Each match becomes an alert with a severity and a confidence score, not an automatic verdict.
Is this a live monitoring feed?
+
No — it's a bounded, point-in-time snapshot for research and coursework, not a production surveillance tool. There's no auth and no write path from the frontend; treat it accordingly.
Can I point it at a different case study?
+
Yes — set CASE_STUDY_ADDRESS in .env and re-run the ingestion and analysis pipeline. Nothing in the dashboard or API is hard-coded to the Poly Network address.
